# Production

## Instructions

1. **Identify Asset Type:** Determine from user input which production type applies
2. **Load Type Guide:** Read the corresponding file from `production-types/`
3. **Resolve Content Source:** Production skills format existing content — check if the source content already exists in `output/` from a prior copywriting skill run. If not, generate the content first using the appropriate copywriting skill, then produce
4. **Reference Messaging House:** Extract visual identity context from `/messaging` using the table below
5. **Load Platform Skill:** Read the platform format skill for the output format (see Production Paths below)
6. **Design and Produce:** Apply type-specific design guidelines, build the deliverable, and export
7. **Self-Evaluate:** Review against the validation checklist

## Production Type Guides

After identifying the asset type, load the corresponding guide:

- **Datasheet:** See `production-types/datasheet.md`
- **Sales One-Pager:** See `production-types/one-pager.md`
- **Executive Brief:** See `production-types/executive-brief.md`
- **Slide Deck:** See `production-types/slide-deck.md`
- **Campaign Kit:** See `production-types/campaign-kit.md`

## Production Paths

Each asset type has a predetermined production format. The skill selects the path — the user doesn't need to specify a format.

| Asset Type | Production Path | Platform Skill | Output |
|---|---|---|---|
| Datasheet | HTML → PDF | `/mnt/skills/public/pdf/SKILL.md` | .pdf |
| Sales One-Pager | HTML → PDF | `/mnt/skills/public/pdf/SKILL.md` | .pdf |
| Executive Brief | HTML → PDF (default) or DOCX (if user needs editable) | `/mnt/skills/public/pdf/SKILL.md` or `/mnt/skills/public/docx/SKILL.md` | .pdf or .docx |
| Slide Deck | Native PPTX | `/mnt/skills/public/pptx/SKILL.md` | .pptx |
| Campaign Kit | Mixed — PDF + PPTX bundle | Both platform skills | folder with multiple files |

**Critical:** Always read the platform skill file before producing. These contain format-specific rules, library usage patterns, and common pitfalls that are essential for producing valid output files.

## Content-First Principle

Production skills format content — they don't invent it. The content pipeline is:

```
Messaging House → Copywriting Skill → Content (markdown) → Production Skill → Deliverable (PDF/PPTX/DOCX)
```

If the source content exists (a battlecard was generated by the enablement skill, a product page was generated by the web skill), the production skill formats it. If it doesn't exist, the production skill should generate the content first using the appropriate copywriting skill's guidelines, then format.

The production skill adds visual design, layout, and format-specific structure. It does not add new messaging claims, new proof points, or new positioning. Everything in the deliverable must trace to the messaging house or the source content.

## Design Principles

These apply across all production types:

- **Branded, not templated.** The output should feel like a designed document from this company, not a generic template with a logo slapped on. Use brand colors, voice, and visual style from profile.md
- **Scannable at every zoom level.** A reader skimming the PDF at 50% zoom should get the key message. A reader studying it at 100% should get the detail. Design the visual hierarchy for both
- **Proof visible, not buried.** Customer quotes, metrics, and logos should appear where they support claims — not in a "proof" section at the end
- **White space is a feature.** Dense pages get skimmed or skipped. Give content room to breathe. A one-pager with 60% coverage is more effective than one with 95% coverage
- **Consistent naming.** Every product name, feature name, and term must match glossary.md. Naming errors in produced documents are the most visible kind of inconsistency

## Validation Checklist

```
Production Quality Check:
- [ ] Content Accuracy: All claims trace to messaging house sources
- [ ] Naming: Product and feature names match glossary.md exactly
- [ ] Visual Hierarchy: Key message visible at skim level
- [ ] Proof Placement: Evidence inline with claims, not deferred
- [ ] Brand Consistency: Colors, voice, and style match profile.md
- [ ] Format Validity: Output file opens correctly in target application
- [ ] Type Alignment: Follows structure from type guide
```

## Output Format

Production skills output finished files, not markdown. The output location follows the campaign structure if the asset is part of a campaign, or writes to `output/production/` for standalone assets:

```
output/
  production/
    vuln-mgmt-datasheet.pdf
    competitive-displacement-deck.pptx
  campaigns/
    q1-launch/
      asset-04-sales-deck.pptx
      asset-06-datasheet.pdf
```

Each produced file should be accompanied by a brief markdown manifest:

```markdown
## Production Manifest
**Asset:** [name]
**Type:** [datasheet | one-pager | executive-brief | slide-deck | campaign-kit]
**Format:** [.pdf | .pptx | .docx]
**Source Content:** [path to source markdown, if applicable]
**Messaging Docs Referenced:** [list]
**Produced:** [date]
```
